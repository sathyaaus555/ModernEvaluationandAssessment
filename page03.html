Topic 03 · Practical AI-assisted assessment

AI-Powered Assessment Creation

12 MIN

Turn a learning outcome into useful assessment tasks using clear prompts, step-by-step execution and educator review.

Start with the learning outcome

Running example · Introductory Python

Learning outcome: Students can write a for loop to process values in a list.

Assessment goal: Check whether students can apply the concept, not merely recall its definition.

Five components of an effective prompt

Role

Who should AI act as?

“Act as an introductory programming assessment designer.”

Context

What must AI know?

“First-year students; Python lists and for-loops.”

Task

What should AI produce?

“Create MCQs, a scenario question and a rubric.”

Constraints

What rules must it follow?

“Target Apply level; no advanced Python features.”

Output Format

How should results appear?

“Use a table with answers and marking criteria.”

Diagnosing a weak prompt · What happens when a component is missing?

The Prompting & Task Execution module treats weak AI output as a clue to which prompt component needs improvement.

Missing or unclear componentLikely output problemAssessment design example
ContextGeneric or off-base outputQuestions ignore the learners' level or syllabus
TaskWrong action or question answeredAI writes explanations instead of the requested MCQs
ConstraintsWrong length or toneQuestions do not follow the requested difficulty or scope
Output FormatWrong shape or presentationMissing four-option structure, answer key or rubric table
Diagnostic tip: Generic output → add context. Wrong action → clarify the task verb. Wrong length, tone or shape → specify constraints or output format. Fix the component that failed rather than rewriting the whole prompt.

Source: Prompting & Task Execution – Module 2, “Diagnosing a Weak Prompt” and “Iterating Prompts to Improve Output.” Assessment examples are adaptations for this presentation. Not every prompt requires all five components; choose according to the task.

Prompt comparison · Vague vs specific

Vague prompt“Create some Python assessment questions.”

Missing context and constraints can lead to generic questions or the wrong difficulty.

Structured prompt

“Act as an introductory programming assessment designer. For first-year students learning Python lists and for-loops, create two Apply-level MCQs and one scenario question aligned with the outcome ‘write a for-loop to process a list’. Avoid advanced features. Provide correct answers, explanations and a 5-mark rubric in a table.”

What AI can draft · Three assessment outputs

01 · Multiple-choice question

Which code correctly prints each number in a list?

  1. for n in [2, 4, 6]: print(n)
  2. for n of [2, 4, 6]: print(n)
  3. print([2, 4, 6][n])
  4. for [2, 4, 6] in n: print(n)

Correct answer: A. Python uses for ... in ... to iterate over list elements. Review: Confirm syntax, distractor quality and the intended cognitive level.

02 · Scenario-based question

Classroom marks

A teacher has a list of marks: [42, 67, 81, 55]. Write a Python for loop that counts how many marks are 50 or above. Explain the result.

Expected result: 3 passing marks. Review: Does the task assess application rather than memorisation?

03 · Example marking rubric

Scenario question · 5 marks

CriterionMarks
Correctly iterates through the list2
Uses the correct pass condition and count2
Reports and explains the result1

Review: Check whether the criteria fairly reflect the intended learning outcome.

Source concept: Module 2 teaches Task Decomposition: break complex work into ordered, checkable steps and verify shared information before producing multiple deliverables. Adaptation: Specify → Generate → Verify → Rubric is an illustrative assessment workflow created for this FDP; it is not a four-step sequence quoted from the module. A rubric is a marking guide that describes criteria and how marks are allocated.

Improve the output · Diagnostic iteration

If the questions are too easy…

Revise the Task / Constraints: “Replace recall questions with Apply-level tasks requiring students to interpret or write code.”

If the format is wrong…

Revise the Output Format: “Present each question with four options, the answer, and a one-sentence rationale.”

Module 2 takeaway: Diagnose the weak component → change that component → compare the new result → stop when further changes add little value. The goal is a usable result, not a perfect prompt.

Suggested live demonstration · 3 minutes

1. Show the vague prompt and discuss what is missing. 2. Run the structured prompt in an AI assistant. 3. Review one MCQ, one scenario and the rubric against the learning outcome.

Ask the audience: “Does this question test what students can do, or only what they can remember?”
